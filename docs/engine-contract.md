# Oak engine extensions: shared contract (v1)

The agreement between `oakvcs-engine` and the Godot, Unity and Unreal extensions.
Changes must be additive: append to the Changelog at the bottom. A breaking
change needs the user's sign-off.

## Principles

1. Pure logic goes in `oakvcs-engine`, built on `oak-core`. It holds no threads,
   spawns no processes, and does no network I/O.
2. Anything that touches `.oak/oak.db`, the working-tree scanner, or the network
   goes through the `oak` CLI. Extensions never open `.oak/oak.db`: a linked
   `oak-core` can be older than the database after `oak upgrade`.
3. Each engine runs the `oak` process with its own async primitive, because each
   must avoid blocking its own editor thread. The library only says what to run
   (`cli.plan`) and what the result means (`cli.parse`).
4. Do not force sharing. UI, editor hooks and process handling stay per-engine.

## Layout

| Thing | Location |
|---|---|
| Crate | `engine/` in the `oak/oak` workspace, package `oakvcs-engine`, lib `oak_engine`, `cdylib` + `rlib` |
| `oak-core` dependency | path dep with `default-features = false` (see Changelog) |
| Header | `engine/include/oak_engine.h`, generated by cbindgen and checked in |
| Conformance fixtures | `engine/fixtures/conformance/*.json` |
| Targets | darwin-arm64, darwin-x86_64, linux-x86_64, linux-arm64, windows-x86_64 |

The engine isn't published: Oak's releases ship the CLI and the Mount app only.
An extension builds the library from this repo with `cargo build -p
oakvcs-engine` at a commit it pins. Always name the package: a workspace-wide
build turns `oak-core`'s `local-repo` on through feature unification.

## C ABI

```c
const char *oak_engine_abi_version(void);          /* static string, "1" */
char *oak_engine_call(const char *request_json);   /* never NULL; free below */
void oak_engine_free(char *response_json);
```

No panic may cross the ABI: catch it and return `internal`. Inputs and outputs
are UTF-8 JSON. Calls are thread-safe.

```json
{"v": 1, "op": "assets.classify", "args": {}}
{"v": 1, "ok": true, "result": {}}
{"v": 1, "ok": false, "error": {"code": "bad_request", "message": "...", "retryable": false}}
```

Error codes: `bad_request`, `unknown_op`, `unsupported_version`, `internal`.
`cli.parse` adds `not_logged_in`, `network`, `conflict`, `dirty_tree`, `locked`,
`ci_blocked`, `cli_too_old`, `cli_failed`. Here `locked` means the repo is locked
(exit code 3). Oak's exit codes are defined in `oak --help`; map from
those, not from stderr text, wherever an exit code decides it.

Follow Oak's JSON rule when parsing CLI output: ignore unknown fields, and treat
an absent field as its default.

## Operations

| Op | Args | Result |
|---|---|---|
| `engine.detect` | `path` | `engine`: `godot`/`unity`/`unreal`/null, from `oak_core::detect_engine` |
| `ignore.template` | `engine` | `contents`. One canonical template per engine |
| `assets.classify` | `engine`, `paths[]` | per path: `kind` (`text`/`binary`/`sidecar`), `merge` (`text`/`none`) |
| `assets.companions` | `engine`, `paths[]` | the set expanded with sidecars, e.g. Unity `.meta`, Godot `.import`/`.uid` |
| `status.rollup` | `changes[]` | per-directory rollup for folder badges |
| `diff.text` | `old`, `new` | hunks via `oak-core` |
| `merge.text3` | `base`, `ours`, `theirs` | merged text or conflicts via `oak-core` |
| `narrative.append` | `existing`, `message` | new branch description text |
| `binary.candidates` | `platform`, `home`, `override`, `path_env` | ordered candidate `oak` paths |
| `version.check` | `cli_version` | `ok`, `minimum`, `capabilities` |
| `cli.plan` | `action`, `params` | `argv[]`, `cwd_relative`, `stdin` (optional), `timeout_ms` |
| `cli.parse` | `action`, `exit_code`, `stdout`, `stderr` | normalized result or typed error |

`cli.plan`/`cli.parse` actions: `status`, `info`, `diff`, `log`, `branch_list`,
`branch_create`, `branch_switch`, `branch_close`, `commit`, `desc_get`,
`desc_append`, `fetch`, `pull`, `push`, `merge`, `restore`, `whoami`,
`ci_status`, `ci_runs`, `ci_logs`, `ci_publish_preview`, `ci_publish`.

`ci_publish_preview` maps to `oak ci publish -e ENV --dry-run --json`, and
`ci_publish` maps to the same command with `--yes`. It adds `--commit` only for a
republish: see the Changelog. An editor must show the preview and get an explicit
click first.

### Details of the operations

Added with the implementation. Where this and a row above seem to differ, this
is what the library does.

- `cli.plan`'s `argv` excludes the binary: `binary.candidates` finds that.
  `cwd_relative` is always `.`, the repo root (`.oak/`'s parent). `stdin` is null
  unless the action needs it. Paths must be repo-relative and are refused
  otherwise. Pass `argv` as an argument list; if a platform forces a shell, the
  extension quotes it.
- Extra `cli.plan` actions: `conflict_status` (`oak conflict status --json`) and
  `version` (`oak --version`). `cli.parse` accepts both.
- `cli.plan` params, all optional unless noted: `diff`: `paths`, `max_bytes`,
  `from` and `to` (both or neither, see below);
  `log`: `limit`, `paths`; `branch_list`: `status`; `branch_create`: `name`,
  `clean`; `branch_switch`, `branch_close`: `name` (required); `commit`: `paths`;
  `desc_append`: `message` (required); `pull`: `continue` or `abort`; `merge`:
  `wait_minutes`; `restore`: `paths` (required, non-empty), `source`; `ci_status`:
  `run`, `commit`; `ci_runs`: `limit`; `ci_logs`: `run` (required), `summary`,
  `failed`, `max_bytes`; `ci_publish_preview`: `environment` (required),
  `workflow`, `branch`; `ci_publish`: those plus `commit` (required, full hash from
  the preview) and `republish` (the preview's value).
- `diff` with `from` and `to` shows one commit: pass its parent and its hash. Both
  are required, because `oak diff HASH` alone compares the commit to the working
  tree. A commit with no parent has no diff in the CLI; `oak tree inspect` lists
  its files.
- `whoami` runs `oak auth status --json`, because `oak whoami` has no JSON.
- `assets.classify` takes an optional `unity_force_text` (default false), and
  returns `assets[]` of `path`, `kind`, `merge`. A format it doesn't know is
  `text`. Unity YAML assets are `binary`/`none` unless `unity_force_text` is true,
  when they are `text`/`text`.
- `assets.companions` returns `paths`. It doesn't touch the disk, so a companion
  may not exist: skip those that don't. It works both ways: a sidecar brings its
  asset.
- `status.rollup` takes the `changes` of a parsed `status` and returns
  `directories[]` of `path` (`""` is the root), `added`, `modified`, `deleted`,
  `renamed`, `total`, `status` (one status, or `mixed`).
- `diff.text` also takes `path` and `context`. It returns `hunks[]` of
  `old_start`, `old_count`, `new_start`, `new_count`, `header`, and `lines[]` of
  `kind` (`context`/`added`/`removed`), `text`, `old_line`, `new_line`. `cli.parse`
  gives `diff` files the same hunk shape, with `no_newline` on a line that had
  the marker.
- `merge.text3` returns `clean`, `text` (the whole file, with diff3 markers when
  not clean) and `conflict_count`.
- `narrative.append` returns `text`, byte for byte what `oak desc --append` makes.
- `binary.candidates`: `platform` is `windows`, `darwin` or `linux`. Returns
  `candidates`; take the first that exists.
- `version.check` accepts raw `oak --version` output and adds `version`.

### What `cli.parse` returns

Fixtures in `engine/fixtures/conformance/cli_parse.json` show every shape. Absent
fields come back as null, false, 0 or empty.

Every typed error from `cli.parse` adds `exit_code`, `oak_code` (Oak's own
`error.code`, or null), `conflict_paths` and `next_commands`, which extensions
can show as they are. `oak_code` is also how to tell cases sharing a code apart:
`repo_not_found` is `cli_failed` with that `oak_code`.

Rules worth knowing, each read off real output:

- `oak pull --json` reports a conflict with exit 5 and a normal receipt, while
  `oak merge --json` uses an `error` envelope whose `conflict_paths` is empty.
  Both are `conflict`; for `merge`, run `conflict_status` to get the paths.
- `oak ci status` exits 1 for failed or no runs and 3 for running. Those are
  states, so `ci_status` returns a result with `state` (`success`, `failure`,
  `running`, `no_runs`, `dispatch_pending`).
- `ci_publish_preview` always returns the preview when there is one, with
  `outcome`, `ready`, `can_authorize` and `problems`. `ci_publish` returns only on
  `authorized`, with `run_id` and `run_url`; any other outcome is `ci_blocked`.
  Pass the previewed commit as `cli.parse`'s optional `expected_commit`: the result
  then has `commit_moved`, true if the head moved and a different commit was
  authorized. Show that to the user; the run has already been authorized.
- Exit 6 covers network, server and auth, so that one case reads the message:
  `not_logged_in`, `ci_blocked` for `merge` (the 412 CI, findings and approvals
  gates), otherwise `network`.
  `retryable` is false when the server answered (`Server error:`).
- Exit 2 from a refused subcommand or flag is `cli_too_old`. Exits 7 and 8 are
  `cli_failed` with `retryable: true`.
- A successful `merge` moves the checkout to `new_branch`, a new generated branch.
- Switching to `main` can fail with exit 1 when the checkout has no local `main`,
  because Oak treats it as server-owned.

### Conformance fixtures

`engine/fixtures/conformance/*.json`, shipped as `oak-engine-fixtures.tar.gz`:

```json
{"name": "cli_parse", "cases": [{"name": "status/status_dirty", "source": "captured",
 "request": {"v": 1, "op": "cli.parse", "args": {}},
 "response": {"v": 1, "ok": true, "result": {}}}]}
```

Send each `request` through the binding and compare the parsed response to
`response` as JSON values: key order doesn't matter. `source` is `captured` (real
CLI output, including four read-only CI calls against oak.space), `derived`
(written from the CLI source because a capture run can't produce it) or `spec`.
`engine/fixtures/capture/` regenerates them against a non-production Oak
server given as `OAK_REMOTE`.

## Asset rules

Workers must verify these against current engine docs, not trust this table.

| Engine | Sidecars, always moved with their asset | Not mergeable (`merge: none`) |
|---|---|---|
| Godot | `*.import`, `*.uid` (both versioned) | binary resources such as `*.res`, `*.scn`, textures, audio |
| Unity | `*.meta` (versioned) | binary assets; YAML scenes and prefabs merge as text only if Force Text serialization is on |
| Unreal | none | `*.uasset`, `*.umap` |

Checked on 2026-11-06. Godot's docs say to ignore `.godot/` and `*.translation`,
and its 4.4 UID article says `.uid` files go beside scripts and shaders and must be
committed. That page doesn't mention `.import`, so that row rests on the addon's
own template. Treating `.gdextension` as UID-bearing is unverified against the
docs. Unity's YAML list comes from its supported-types page. `.meta` in folders
under `Assets/` and `Packages/` and Unreal's rows were not re-checked against docs.

`ignore.template` is `oak_core::GameEngine::oakignore_contents`, the same text
`oak init` writes. It replaces the extensions' own templates. The Unity one drops
the addon's `Build*/`, which would silently untrack `Assets/BuildTools/`.

## Out of scope

File locks and overlapping-edit detection are not part of this project. Do not
add lock commands, lock UI, or server changes for them. Extensions surface binary
conflicts the way they do today.

## Test and coverage bar

| Layer | Runs in | Line coverage gate |
|---|---|---|
| `oakvcs-engine` | merge gate, `cargo-llvm-cov` | 90% |
| Engine-free layer of each extension | merge gate | 80% |
| Godot in-editor tests | merge gate, headless Docker | Report only, unless a credible tool exists |
| Unity and Unreal in-editor tests | jobs on `unity` / `unreal` runner labels, none exist yet | None |

Every extension also has:

- a conformance job that replays `engine/fixtures/conformance/*.json` through its
  own binding
- a real-CLI integration test against a non-production Oak server, given as
  `OAK_REMOTE` (never oak.space)

A job that needs a missing runner must not sit in the merge gate. Unverified code
must be listed as unverified in the branch description, never implied as passing.

Each repo gets `.oak/workflows/ci.yml` (`on: push`) and
`.oak/workflows/release.yml` (`workflow_dispatch`, `environment: production`),
triggered with `oak ci publish -e production`. The release workflow packages the
extension. Marketplace submission stays manual;
ship a ready-to-upload package and `docs/marketplace-checklist.md`.

## Worker rules

- Use `oak`, never `git`, in Oak repos.
- Work in your own new directory under `/Users/zdgeier/oak/`. Do not touch
  existing sibling checkouts.
- Push reviewable branches with `oak finish`. Do not `oak merge`.
- Do not run `oak ci publish`, publish anything, create environments or secrets,
  register runners, or sign in to marketplaces. List those as handoff items.
- Never run a real deploy to test a release workflow; use `--dry-run`.

## Changelog

- 2026-11-06: v1 drafted.
- 2026-11-06: removed file locks at the user's request: `lock_*` actions,
  `lock_held`, `locks_unsupported`, `lockable`. `merge` values are now
  `text`/`none`. Four workers, not five.
- 2026-11-06 (shared-crate worker, all additive):
  - Implemented in `oak/oak`; this file moved here. "Details of the operations",
    "What `cli.parse` returns" and "Conformance fixtures" are new.
  - `oak-core` is a path dep in `engine/Cargo.toml`, not the workspace entry:
    that entry keeps default features on, and a member can't turn them off by
    inheriting it. Purity is enforced by `make engine-pure`.
  - New `cli.plan` actions `conflict_status` and `version`.
  - New optional `unity_force_text` for `assets.classify`: whether a project uses
    Force Text can't be derived from a path.
  - `whoami` is `oak auth status --json`.
  - `oak close --json` is used for `branch_close`, and `desc_append` goes over
    stdin (`--file -`).
  - `ci_publish` differs from v1, which said to pass the exact previewed commit.
    `--commit` is the CLI's republish flag: it sets `republish` on the
    authorization even at the branch head, while the preview says false. The plan
    now matches the CLI's own recommended command and names the commit only for a
    republish. The cost is that a plain head publish isn't fenced to the preview:
    the CLI re-previews, so a head that moves between preview and click gets
    authorized. The CLI has no flag to prevent that. `commit_moved` reports it after
    the fact; closing the gap needs a CLI change. Neither form has run for real.
  - `diff` gained `from` and `to`, and `cli.parse` gained `expected_commit`.
  - The CLI minimum is 0.110.0, the first with `oak ci publish`.
